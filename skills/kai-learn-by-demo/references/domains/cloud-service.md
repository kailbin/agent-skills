# Domain：云服务

适用于：公有云的托管服务（AWS、阿里云、GCP、Azure），例如对象存储、消息队列、NoSQL、Serverless 函数、事件总线、密钥与参数管理。
重点放在后端开发最常用的服务上，用 Java SDK 调用。

## 1. 知识点维度

| 级别 | 维度 | 说明 |
|---|---|---|
| L1 | SDK 基础 | 客户端创建、凭证提供链、region、同步 vs 异步客户端、客户端复用 |
| L1 | 单个服务的核心操作 | 每个服务一个模块：最核心的增删改查 / 收发 |
| L2 | 服务的进阶特性 | 例如对象存储的预签名 URL 与分段上传、队列的死信与 FIFO、NoSQL 的二级索引与条件写入 |
| L2 | 框架集成 | Spring Cloud AWS 这类集成库：注解式监听、配置注入 |
| L2 | 服务组合 | 扇出（发布订阅 → 多个队列）、事件驱动（存储事件 → 函数） |
| L3 | SDK 内部机制 | 请求执行管线、拦截器、重试与退避、超时分层；**手写请求签名**并与 SDK 结果比对 |
| L3 | 托管服务的语义 | 投递语义（至少一次）、最终一致性、分区与热点；用实验证明并给出应对方式 |
| L4 | 权限 | 最小权限策略、角色与临时凭证 |
| L4 | 基础设施即代码 | CDK / Terraform 定义示例中用到的资源 |
| L4 | 观测与成本 | 云监控指标与告警；各服务的计费维度，示例中哪些做法在生产环境会很贵 |

## 2. 演示道具

- **默认使用本地模拟环境，不产生费用**：LocalStack（一个端点模拟多个服务），或者单服务模拟器
  （S3 → MinIO、SQS → ElasticMQ、DynamoDB → DynamoDB Local）。生成前核对模拟器当前的版本和授权要求（是否需要 token、哪些服务免费）。
- 客户端工厂放在 common 中，通过 `endpointOverride` + 配置在本地 / 真实环境之间切换，**业务代码不改动**。
- 资源由初始化脚本或代码**幂等**创建，用户不需要去控制台操作。
- 只有用户明确要求时才使用真实云账号：README 顶部提示**可能产生费用**，提供 `cleanup.sh`，使用独立的 profile。

## 3. 必做实验

- 凭证与 region 的解析顺序：故意不配置 / 配错，观察报错。
- 投递语义：模拟消费者崩溃，证明消息会被重复投递，再实现幂等消费。
- 一致性：写入后立即读取，观察（或说明）最终一致的情况。
- 每个 API 调用旁边用 `// 【生产】` 标注所需的权限和限额（Quota）。

## 4. 常见的坑

- region 未配置或与资源所在的 region 不一致。
- 本地模拟环境与真实服务的差异（例如 S3 需要 path-style 访问）。
- 消息处理完没有删除 / 确认，导致重复消费。
- 用全表扫描代替按键查询，性能和费用都会出问题。
- 每次请求都新建 SDK 客户端，导致连接与线程资源泄漏。
- Serverless 函数中在 handler 内初始化客户端，没有利用执行环境复用。
- **真实凭证写进了代码或配置文件**：示例中只允许出现本地模拟环境的假值。

## 5. 与用户熟悉的技术对照

| 云服务 | 类似于 | 关键区别 |
|---|---|---|
| SQS | RocketMQ / Kafka | 没有分区和消费位点，靠可见性超时实现可靠性 |
| DynamoDB | MySQL / Redis | 为访问模式建模，而不是为实体建模 |
| S3 | MinIO / OSS | 「目录」只是 key 的前缀 |
| Lambda | 线程池中的任务 | 有冷启动、执行环境复用、最长执行时间限制 |
