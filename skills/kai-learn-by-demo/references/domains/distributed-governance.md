# Domain：分布式治理

适用于：熔断、限流、隔离（舱壁）、重试、超时、负载均衡、服务注册与发现、配置中心、网关、链路追踪等「保护和管理服务间调用」的组件。
例如 Spring Cloud CircuitBreaker / Gateway / LoadBalancer、Resilience4j、Sentinel、Nacos、Consul、Micrometer Tracing。

## 1. 知识点维度

| 级别 | 维度 | 说明 |
|---|---|---|
| L1 | 基本用法 | 最小的「保护一次调用」或「注册 / 发现一次」 |
| L1 | 配置与策略 | 关键参数的含义；**多种配置来源同时存在时的优先级**（YAML、代码、远程配置） |
| L1 | 失败的分类 | 哪些失败要处理、哪些要忽略（如 4xx）；超时与降级 |
| L2 | 集成点 | 与 HTTP 客户端、RPC 框架、网关、响应式栈的集成，每个集成点一个模块 |
| L2 | 可观测性 | 事件、指标、端点；当前框架版本下哪些能用、哪些不能用 |
| L2 | 实现对比 | 抽象层有多种实现时，用**同一份业务代码**对比不同实现的行为 |
| L3 | 核心算法 | 状态机、滑动窗口、令牌桶、一致性哈希、心跳与剔除……手写简化版 + 对照测试 |
| L3 | 执行模型 | 被保护的代码运行在哪个线程上；上下文（traceId、用户、事务）能否传递 |
| L3 | 组合顺序 | 多个治理组件嵌套时，顺序对结果的影响 |
| L4 | 调参 | 用模拟器量化参数的代价（误判 vs 发现延迟） |
| L4 | 监控告警 | Prometheus 指标、看板、告警规则 |
| L4 | 分层与依赖分级 | 强弱依赖、超时预算、网关层与服务层的分工 |
| L4 | 运维干预 | 强制开关、只观察不拦截、动态调参 |

## 2. 演示道具

- **可以注入故障的下游服务**（必备）：运行时通过接口切换 正常 / 慢 / 报错 / 随机失败 等模式，并统计**实际收到的请求数**。
  请求数是证明「熔断 / 限流确实拦住了流量」的最直接的证据。
- **连续调用的观察接口**：`/demo/burst?n=` 一次调用 N 次，返回每次的结果来源（真实 / 降级）、组件状态、耗时、执行线程。
- 统一返回体中带一个「来源」字段（downstream / fallback），一眼就能区分真实结果和降级结果。
- L3、L4 的模拟实验注入**可控时钟**，几毫秒内模拟几分钟的流量。

## 3. 必做实验

- 完整的生命周期：正常 → 故障 → 组件介入（熔断 / 限流 / 摘除） → 恢复。
- 「被拦截的请求没有到达下游」：对比调用方的请求数与下游收到的请求数。
- 配置优先级：同一个对象在多个配置来源中设置不同的值，查看最终生效的值。
- 执行线程与上下文：在被保护的代码中打印线程名、ThreadLocal、MDC。
- 有保护 vs 无保护：在固定大小的线程池（模拟容器线程）下比较总耗时与 P95。

## 4. 常见的坑（调研时逐一检查）

- **默认值陷阱**：默认超时、默认窗口、默认是否启用（例如 TimeLimiter 默认 1 秒）。
- **配置被静默覆盖**：多个配置来源的优先级，覆盖时没有任何提示。
- **线程切换**：为了实现超时或隔离，调用被提交到其他线程，ThreadLocal 丢失；关闭线程池时，超时也随之失效。
- **失败感知不到**：网关转发 5xx、业务代码自己 catch 了异常，都不会被计为失败。
- **异常被包装**：ExecutionException、CompletionException、框架自定义异常，降级时要先解包。
- **抽象层不保证行为一致**：同一个抽象接口，不同实现的语义可能完全不同，必须实测。
- **与新版本框架的兼容性**：例如第三方库的健康检查、Actuator 端点基于旧版本 API 编译，在新版本下失效。

## 5. 示例：Spring Cloud CircuitBreaker（2026-11 生成）

- 道具：`cbdemo-downstream`（`/chaos` 切换故障模式，统计 receivedCount）
- L1：Factory 入门、配置优先级、超时与分类降级；L2：响应式、舱壁、OpenFeign、网关、指标、三种实现对比、HTTP Interface；
  L3：手写熔断器、手写时间窗口、Factory 源码与线程模型、装饰器顺序；L4：调参模拟器、Prometheus/Grafana、分层保护、运维开关
- 实测中最有价值的发现：业务代码默认运行在 Factory 的线程池中；disable-thread-pool 会让超时失效；
  Spring Retry 实现在默认配置下不会打开熔断；YAML instances 会静默覆盖代码配置
