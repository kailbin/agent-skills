# Domain：框架与库

适用于：在进程内使用的框架和库，例如 Spring Data JPA、MyBatis、Reactor、Quarkus、JSpecify、Jackson、Netty。
也是其他 domain 都不合适时的默认选择。

> 这份 domain 还没有经过实际项目的检验。第一次使用后，按 SKILL.md 第 7 步把经验沉淀回来。

## 1. 知识点维度

| 级别 | 维度 | 说明 |
|---|---|---|
| L1 | 核心用法 | 官方 Getting Started 的范围；最常用的 API / 注解 |
| L1 | 配置 | 关键配置项与默认值；自动配置做了什么 |
| L2 | 常用特性 | 每个特性一个模块，按「使用频率」排序 |
| L2 | 集成 | 与 Spring Boot、测试框架、其他常用库的集成 |
| L2 | 扩展点 | 框架提供的扩展接口：自定义一个实现 |
| L2 | 测试 | 怎样为使用这个框架的代码写测试 |
| L3 | 核心机制 | 2~4 个最关键的机制，例如代理、字节码增强、注解处理、事件循环、缓存；**手写简化版 + 对照测试** |
| L3 | 生命周期 | 启动时做了什么、一次调用经过了哪些步骤；给出断点位置 |
| L4 | 性能 | 常见的性能问题（如 N+1 查询、反射开销、对象分配），用基准测试量化 |
| L4 | 升级与兼容 | 大版本升级的主要变化与迁移方法 |

## 2. 演示道具

- 大多数模块不需要外部依赖；需要数据库时，优先用内嵌数据库（H2）或 Testcontainers。
- 观察工具：开启框架的调试日志（如 SQL 日志），或者在关键位置打印调用栈，让「框架替你做了什么」变得可见。
- 基准测试用 JMH（Java）/ pytest-benchmark（Python），不要用简单的 currentTimeMillis 计时下结论。

## 3. 必做实验

- 「框架替你做了什么」：同一个功能，用框架实现一次，再不用框架手写一次，对比代码量与行为。
- 默认行为：关闭 / 修改一个关键的默认配置，观察行为变化。
- 一个典型的误用：重现最常见的错误用法及其现象（如 JPA 的 N+1、懒加载异常）。

## 4. 常见的坑

- 自动配置的条件（`@ConditionalOnXxx`）没有满足，功能静默不生效。
- 代理导致的问题：自调用不经过代理、final 方法无法被代理。
- 默认值在大版本之间发生了变化。
- 与其他库的版本冲突（依赖树中出现两个版本）。
